My account

The My Account area stays built on the real WordPress/WooCommerce /my-account/ page (the [woocommerce_my_account] shortcode), dressed by the theme's own templates — woocommerce/myaccount/*.php — rather than replaced by dedicated views. Two endpoints of the theme's own (wishlist, support request) are added on top of WooCommerce's native ones.

Sidebar and dashboard

woocommerce/myaccount/my-account.php now places the navigation and content in a 260px 1fr grid (.account-layout) instead of WooCommerce's default stacked layout. woocommerce/myaccount/navigation.php delegates rendering to template-parts/account/sidebar.php: a user info block (avatar/name/email, Solar_Template\Account\AccountProfile) followed by an icon-based navigation (Solar_Template\Account\AccountNav).

Solar_Template\Account\AccountEndpoints fully rebuilds the account menu in the design handoff's own order and wording (Dashboard, Orders, Wishlist, Addresses, Downloads, Support request, Settings, Logout) — WooCommerce's own "Payment methods" item, absent from the design, is dropped from the menu (still reachable at its direct URL). The same class registers the theme's two custom endpoints (wishlist, sav) via add_rewrite_endpoint(); their real content is wired in later steps of this area's build-out.

woocommerce/myaccount/dashboard.php delegates to template-parts/account/dashboard.php a greeting, 4 stat cards (in-progress orders, total orders, wishlist, active support requests — computed by Solar_Template\Account\Dashboard from the customer's real orders), a recent orders table with a colored status badge (Solar_Template\Account\OrderStatusPresenter) and 3 quick links. An already-delivered order offers a "Reorder" link (Solar_Template\Account\ReorderHandler) that adds every item of that past order back into the cart in a single, nonce-protected request.

Technical decision: every menu label/order comes from this theme's own translation catalog rather than WooCommerce's own defaults (e.g. "Settings" rather than core's "Account details"), to stay faithful to the design's wording regardless of which core WooCommerce translation is installed. The "Wishlist"/"Support" stat counts start at 0 until those two features are themselves built, then get wired to their real data once ready.

Verified end to end in the real Docker environment with WooCommerce active (permalinks set to a non-"plain" structure, a WooCommerce requirement for its own endpoints): a test customer account with two real orders (one "in transit", one "delivered") shows exact stats and a recent orders table, the active navigation item matches every visited page, and the "Reorder" link genuinely adds the right items/quantities to the cart (confirmed via the real cart summary). No PHP warning or error observed.
