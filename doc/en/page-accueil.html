Home page

front-page.php assembles the home page section by section, each one a self-contained template-part under template-parts/front-page/ — as each is built.

Hero

template-parts/front-page/hero.php renders the full-viewport hero (dark background, two-column grid): a gold eyebrow label, a three-line heading (the middle line in accent gold italics), a subtitle, two calls to action, a list of trust badges, and a media block with a floating "favorite pick" card (title, price, stock progress bar). Styled by assets/scss/_hero.scss, built entirely from the shared design tokens — see Design system.

All of its content (eyebrow, heading, CTAs, trust badges, floating card) comes from a single filterable helper, solar_template_hero_config() in functions.php — the same convention as solar_template_footer_config() and the other common-structure helpers. No real data (a featured product, an image) is wired in at this step: this is placeholder editorial content, ready for the future "Home page" administration tab to hook into.

Technical decision: both hero CTAs point at the WooCommerce shop page (solar_template_shop_url()), matching the mockup — there is no dedicated "new arrivals" view yet to point the second one at, for the same reason as the primary navigation (see Common structure).

Verified in the real Docker environment, in both installed languages (French and English): the section renders without any warning or error, fully translated according to the site's active language. The highlight card's price formatting is not locale-aware yet ("129,00 €" in both languages) — the same known, documented limitation as template-parts/product-card.php's identical placeholder helper, superseded by WooCommerce's own wc_price() once wired to a real product.

Featured products

template-parts/front-page/featured-products.php renders a masonry grid (4 columns, a purely visual vertical offset on the 2nd and 4th card) of the WooCommerce products actually marked "Featured" from the product edit screen (solar_template_get_featured_products() in functions.php, backed by wc_get_products(['featured' => true])), each rendered with the product card component already in place (see Design system) rather than new markup.

Unlike the hero, this section reads real WooCommerce data: image, price, struck-through price and discount percentage when the product is on sale (an "On Sale" badge) all come straight from the WC_Product object (solar_template_map_product_to_card_args()). The product card's color swatches stay empty at this step: no reliable color attribute data is wired in yet (planned for a later catalog/product page step).

Technical decision: the section does not render at all when no product is marked as featured (WooCommerce inactive, or none marked yet), rather than showing an empty grid — the same graceful-degradation logic used throughout the theme.

Bug avoided before it caused a translation regression: the "On Sale" badge was initially going to reuse the English source string "Sale", already used by the "Promotions" navigation link with a different French translation for the same English text — the theme's translation catalog does not distinguish strings by context yet. Fixed by using a distinct source string ("On Sale") for the badge.

Verified end to end in the real Docker environment with WooCommerce active: two test products (one on sale) created and marked as featured confirm correct rendering (price, struck-through price, computed discount percentage), and unmarking them as featured makes the whole section disappear — test products deleted after verification.
