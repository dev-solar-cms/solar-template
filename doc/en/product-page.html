Product page

single-product.php renders a WooCommerce product's own page. This template is built section by section, same convention as front-page.php for the home page.

Gallery

Solar_Template\Product\ProductGallery::images() reads the product's featured image, then its WooCommerce gallery (WC_Product::get_image_id()/ get_gallery_image_ids()), deduplicated, and returns a flat list (id, URL, alt text). single-product.php computes this list (falling back to WooCommerce's own placeholder image when the product has no image at all) and passes it to template-parts/single-product/gallery.php, which only renders it — same convention as Catalog\ProductCardMapper/template-parts/product-card.php for the product card.

The main image (4:5 ratio) is followed by a strip of thumbnails, one per image — the strip does not render at all as long as the product has a single image. Clicking a thumbnail swaps the main image with no page reload (assets/js/product.js, initProductGallery()), and marks that thumbnail active.

Technical decision: the mockup's "Enlarge" (zoom/lightbox) button is deliberately not built at this stage — its behaviour is not specified beyond the mockup itself, same reasoning as archive-product.php's grid/list view toggle.

Verified end to end in the real Docker environment with WooCommerce active: a product with no image at all confirms the fallback to WooCommerce's own placeholder image (no thumbnail strip); a test product with a featured image and a gallery image confirms the thumbnail strip renders, the first one marked active — test product and images deleted after verification.
