Blog

The blog stays built on WordPress' own real pages/templates: the index (home.php, loaded for the "Posts page" configured under Settings > Reading — this theme using a static homepage, front-page.php), category/tag archives (archive.php, which WordPress automatically falls back to when no dedicated category.php/tag.php exists — same reasoning as archive-product.php for WooCommerce) and the article page (single.php). No fake article: categories, tags, the featured article and related articles all come from real WordPress data.

Technical decision: at the time this page was built, no separate "Posts page" was configured (Settings > Reading was set to "Your latest posts", so the homepage and the blog index technically coincided at the same URL) — fixed by creating a dedicated homepage and a "Blog" page, then configuring Settings > Reading to "A static page" with those two pages respectively. Verified the homepage (front-page.php) still renders correctly after this change (the front page stays first in WordPress' own template hierarchy whenever it exists, regardless of this setting).

Blog index and archives

home.php assembles a dark hero (editorial copy, filterable through Solar_Template\Blog\BlogHero::heading(), same convention as the home page's other editorial sections), a sticky row of category pills (template-parts/blog/category-filter.php, Solar_Template\Blog\CategoryFilters::items() — every pill is a real link to that category's own archive, no JavaScript needed), the featured article on the first page only (see below), then a 3-column grid of the main query's real posts and its pagination.

archive.php shares the exact same structure for category/tag archives, with a hero built from the real displayed term's own data (Solar_Template\Blog\BlogHero::archive_heading() — the term's real name/ description, no editorial placeholder) instead of the index's own copy, and without the featured article block (specific to the unfiltered index).

Pagination (template-parts/blog/pagination.php, Solar_Template\Blog\BlogPagination::links()) is built directly on top of WordPress' own native paginate_links(), restyled into circles, rather than a custom implementation.

Verified end to end in the real Docker environment: 12 test articles spread across 3 real categories (one marked featured) confirmed the hero, the active pill per visited page, the grid, and real 2-page pagination; category and tag archives showed the right articles. Test data removed after verification, no PHP warning or error observed.

Featured article

The featured block (a 50/50 grid, template-parts/blog/featured-article.php) is backed by WordPress' own native "Sticky post" feature (Solar_Template\Blog\FeaturedPost::current() reads the sticky_posts option directly) rather than a new custom field — no sticky post, and the block simply does not render. To avoid it appearing twice, that article is excluded from the numbered grid below (Solar_Template\Blog\BlogController::exclude_featured_post(), a pre_get_posts hook scoped to the index's own main query).

Verified end to end in the real Docker environment: marking a test article as sticky shows it correctly at the top of the index (and only there, never in the grid), removing it makes the block disappear entirely. Test article removed after verification.

Article grid and pagination

The grid (template-parts/blog/grid.php) reuses the existing design system's blog card component as-is (template-parts/blog-card.php, Solar_Template\Blog\PostCardMapper::map()), already used by the home page's blog preview — no component duplicated. Navigating between archive pages works through plain links (?paged=N), no JavaScript required.

Blog article

single.php renders a breadcrumb (Home / Blog / truncated title), a full-width featured image (21:8 ratio, dark gradient overlay), the article's meta line (category, date, real reading time computed by Solar_Template\Blog\ReadingTime), the title, an author bar with a native "Share" button (assets/js/blog.js, initArticleShare(): the browser's own Web Share API where available, a "copy link to clipboard" fallback otherwise), then the article's real content (the_content()) with rich typographic styling (blockquotes, figures/captions, lists).

Below that: the article's real WordPress tags as pills, an author card (a real avatar or initial, the author's real WordPress profile bio — the native "Biographical Info" field, no invented editorial content — entirely hidden with no bio filled in), and a "Related articles" section (same category, same card component as the grid).

Technical decision: the design handoff's own "Save" button and view counter ("1,247 views") have no defined feature anywhere else in the project (no article-bookmarking system, no native WordPress view counter) — deliberately left out rather than inventing an unspecified feature, same reasoning as other steps in this project.

Verified end to end in the real Docker environment: a test article with an H2 heading, a blockquote, a captioned image, a list and two tags shows every piece of rich formatting matching the design; the Share button genuinely copies the article's real link. Test article and data removed after verification, no PHP warning or error observed.
